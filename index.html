🔑Context window requirement: Hermes rejects any model with less than 64,000 tokens of context. This is non-negotiable and it's the #1 reason setups fail — the config in step 03 handles it.
02
Add OmniRoute as a custom endpoint
Settings → Providers → Custom Endpoints

Open Hermes → click the ⚙ Settings gear (bottom-left) → Providers → Custom Endpoints → click "+ New Endpoint". Fill in exactly these values:

FieldValue to Enter
Nameomni-routeAny friendly label — this is just for you
Provider IDomnirouteAny unique id for this endpoint
Endpoint URLhttp://localhost:20128/v1⚠️ Must include /v1
Default ModelautoOmniRoute picks the best free model automatically
Context131072🚨 MUST be 64000 or higher. 131072 (128K) is recommended
API Keysk-your-key-hereThe key you copied in Part 3, step 05
🚨Context must be 64000+. If you leave it at the default 16000, Hermes refuses to start and shows: "Model has a context window below the minimum 64,000 required by Hermes Agent." Set it to 131072.

Click Save, then click "✦ Use" to activate the endpoint.

03
Test & start a session
Verify it works, then just talk to it

Still in Settings → Custom Endpoints, click "✦ Test" on your omni-route endpoint. Look for a green checkmark.

PowerShell — health check
PS > curl http://localhost:20128/health
# expect: {"status":"ok"}

Then in Hermes click "+ New session" and send any message.

Point it at OmniRoute
This replaces your Anthropic login entirely

Run this in PowerShell — it writes the config file for you:

PowerShell

Paste this into the file and save:

    "ANTHROPIC_BASE_URL": "http://localhost:20128",
    "ANTHROPIC_AUTH_TOKEN": "sk-your-key-here"

}
🚨No /v1 here. Claude Code uses the Anthropic gateway root — http://localhost:20128. Adding /v1 breaks it. (This is the opposite of the Hermes and Codex settings — that's normal, the APIs differ.)

02
Create the config file
Modern Codex reads config.toml only
🚨Codex v0.137+ only reads ~/.codex/config.toml. The old config.yaml from the legacy npm CLI is silently ignored — this is why some guides fail with no error message.
PowerShell — create the file
PS > mkdir -Force $env:USERPROFILE\.codex
PS > notepad $env:USERPROFILE\.codex\config.toml

Paste this and save:

~/.codex/config.toml
model_provider = "omniroute"

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://localhost:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
🔐Note env_key — Codex reads the key from an environment variable, never from the file itself. Set it in step 03.
03
Set the API key & test
Make it permanent, then verify

Set it permanently for your user account:

PowerShell
[System.Environment]::SetEnvironmentVariable(
  "OMNIROUTE_API_KEY",
  "sk-your-key-here",
  "User")

For this terminal session only (do this too, so you can test right now):

PowerShell
PS > $env:OMNIROUTE_API_KEY = "sk-your-key-here"
PowerShell — test
PS > codex "what is 2+2?"

5
Fix common problems
Every one of these comes up — here's the fix
"context window below the minimum 64,000"
Hermes only. Your Context field is set too low — usually left at the 16000 default.
→ Set Context to 131072 in Settings → Providers → Custom Endpoints.
Codex ignores every setting you change
You edited config.yaml. Codex v0.137+ only reads config.toml — and it fails silently.
→ Rename it: ~/.codex/config.toml
Claude Code: 404 / "invalid base URL"
You added /v1 to ANTHROPIC_BASE_URL. Claude Code uses the gateway root, not the OpenAI-style path.
→ It must be exactly http://localhost:20128 — no trailing slash, no /v1.
"Connection refused" / nothing responds
OmniRoute isn't running. The window you started it in was closed, or the machine rebooted.
→ Re-run omniroute in PowerShell and leave that window open.
Everything works but responses are slow
Free providers have low rate limits, and OmniRoute is retrying a provider that just gave up.
→ Connect 2–3 more free providers in the dashboard. More providers = faster failover.
npm install fails on version
Node.js is too old. OmniRoute needs 22.22.2+ or 24.x.
→ Check with node --version, upgrade if needed.
"npm warn ERESOLVE"
Nothing. This is a peer-dependency notice, not an error.
→ Ignore it. The install completed successfully.
6
9Router — the alternative
OmniRoute's parent project. Smaller, leaner, and worth having as a backup

OmniRoute began life as a fork of 9Router — both are free, MIT-licensed, and run entirely on your own machine. They're similar enough that 9Router is a genuine drop-in alternative if you'd rather use it, and different enough that having both gives you router-level redundancy.

Aspect9RouterOmniRoute
Installnpm i -g 9routernpm i -g omniroute
Providers40+350+
Port2012820128
Token savingRTK — 20–40%12 compression engines — 15–95%
QuotasDashboard + reset countdownsDashboard + analytics
Best forMaximum squeeze on your existing subscriptionsWidest provider choice, fastest setup
⚠️They both use port 20128 — they cannot run at the same time. To switch, close the OmniRoute window first, then start 9Router. To run both, change one of the PORT values and point your agent at that port instead.

To try 9Router instead, the setup is nearly identical:

Install & run
npm install -g 9router
9router
# dashboard: http://localhost:20128

Everything in Parts 3–5 stays the same. Only the package name changes.

💡My suggestion: install OmniRoute as your daily driver. Keep 9Router installed as a backup — if OmniRoute ever breaks on an update, you're one command away from working again.
